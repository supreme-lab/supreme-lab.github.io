01 — Abstract

Overview

Large language models are becoming deep agents that plan, persist state, and invoke tools — shifting safety failures from unsafe text to unsafe trajectories. We introduce AgentFence, an architecture-centric security evaluation that defines 14 trust-boundary attack classes across planning, memory, retrieval, tool use, and delegation, and detects failure via trace-auditable conversation breaks: unauthorized/unsafe tool use, wrong-principal actions, state/objective integrity violations, and attack-linked deviations.


Holding the base model fixed, we evaluate eight agent archetypes under persistent multi-turn interaction and find substantial architectural variation in mean security break rate (MSBR), from 0.29 ± 0.04 (LangGraph) to 0.51 ± 0.07 (AutoGPT). The highest-risk classes are operational: Denial-of-Wallet 0.62 ± 0.08, Authorization Confusion 0.54 ± 0.10, Retrieval Poisoning 0.47 ± 0.09, and Planning Manipulation 0.44 ± 0.11, while prompt-centric classes remain <0.20 under standard settings. AgentFence reframes agent security around what matters operationally: whether an agent stays within its goal and authority envelope over time.

02 — Contributions

What We Contribute

C1

Unified Attack Taxonomy

14 classes (A1–A14) pinpointing trust-boundary violations across prompt/state injection, planning manipulation, tool-use hijacking, retrieval poisoning, delegation abuse, authorization confusion, and denial-of-wallet.

C2

Architecture Isolation Protocol

Isolates agent vulnerabilities by fixing the base model and systematically varying control flow, memory handling, tool permissions, and delegation semantics across representative agent archetypes.

C3

Conversation Break Formalism

Objective, evidence-backed criteria certifying when an agent is no longer pursuing the correct goal within its authorized capability envelope — enabling outcome-based security evaluation beyond text-only judgments.

C4

First Comparative Security Map

Using AgentFence on eight widely used archetypes, delivers the first comparative map of structurally exposed attack classes, surfacing near-universal failure modes that persist despite prompt-level safeguards.

04 — Methodology

Threat Model & Evaluation Protocol

🎯

Post-Deployment Adversary

Interface-only adversary with no access to model weights or infrastructure. Influence only through intended channels: user prompts, retrieved content, tool outputs, shared memory, and inter-agent messages.

🔬

Fixed Model, Varying Architecture

All experiments use Qwen2.5-32B-Instruct to isolate architectural effects. 91 HotpotQA instances with stable entities and unambiguous ground truth, converted into multi-turn research workloads.

↺

Multi-Turn Adversarial Stressing

Attacks applied gradually across turns without agent state resets, interleaved with task-consistent queries. Measures whether adversarial influence propagates into long-horizon failures.

📋

Trace-Auditable Breaks

Each run yields an immutable trace with transcript, tool calls, and planner/state events. Security breaks certified via five predicates: UTI, UTA, WPA, SIV, ATD.

🏷️

Attack-Link Attribution

Explicit AL flag prevents conflating baseline task errors with security vulnerabilities. AL=1 only when trace evidences non-authoritative content crossing a trust boundary. Annotator agreement κ=0.81.

⚙️

Three-Dimension Payloads

Payload strength controlled along explicitness (directive vs. implicit), persistence (single-turn vs. repeated), and scope (local vs. cross-task).

06 — Key Findings

What AgentFence Reveals

Operational risks dominate prompt-centric ones

The four highest-break-rate classes (A13, A14, A6, A5) are all trajectory-level stateful failures. Prompt-centric classes (A1, A2) remain below 0.20 under standard configuration — confirming that token-level safeguards do not address dominant operational risks.

Architecture matters more than prompts

MSBR spans a 76% relative range (LangGraph: 0.29 → AutoGPT: 0.51) while holding base model and tasks fixed. Architectures with broader tool scope, higher retry budgets, or weaker planner/memory/tool authority separation exhibit systematically higher break rates.

Authorization confusion is the upstream root cause

Exposure to A14 (Authorization Confusion) correlates with downstream failures in Objective Hijacking (ρ ≈ 0.63) and Tool-Use Hijacking (ρ ≈ 0.58). Ambiguous trust boundaries between planner, memory, and tool authority create a shared root from which failures compound across layers.

82% of breaks are boundary or authority violations

SIV (31%) + WPA (27%) + UTI/UTA (24%) = 82% of all security breaks. AgentFence failures are dominated by who acted with what authority and what state was corrupted, not merely wrong answers. Attack-linked task deviation (ATD) contributes only 18%.

Two separable classes of fixable risk

Configuration elasticity separates risk types: A13 (DoW) jumps 0.58→0.81 and A9 (Delegation) more than doubles under permissive settings — "knob-fixable" by tightening budgets/scope. In contrast, A6 and A5 change <0.10, revealing deeper trust-boundary failures inelastic to any configuration control.

Persistent memory amplifies all stateful attacks

Ablation studies show that disabling persistent memory writes reduces Retrieval Poisoning and Planning Manipulation breaks by up to 35%. Removing retry loops significantly lowers Denial-of-Wallet exposure. Long-horizon state propagation and unbounded retries are the two primary structural risk factors.

07 — Conclusion

The Path Forward

Deep agents convert language into privileged, time-dependent actions. As autonomy, persistence, and delegation become standard, dominant security failures shift from unsafe text to unsafe trajectories — actions executed under the wrong goal, with the wrong authority, with consequences that compound across steps. AgentFence addresses this shift by evaluating security at the level of architecture, using a taxonomy of deep-agent attack classes and trace-auditable conversation-break predicates to expose structural vulnerabilities across archetypes.


Securing autonomous AI systems will require more than better prompts or filters — it demands understanding where agents trust too much, how that trust propagates across time, and which design choices systematically amplify risk. AgentFence provides a foundation for that diagnosis and comparison before deployment at scale.

Reproducibility: Upon acceptance, a versioned AgentFence artifact will be released including agent implementations, the attack harness (per-class payload families, injection points, strength controls), and the semi-automatic labeling protocol — to enable independent reproduction and audit.
