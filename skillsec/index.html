§ 1 — Abstract

Overview

Open agentic platforms have gained popularity by enabling community contributors to publish reusable skills that agents can invoke at runtime — OpenClaw alone now hosts more than 60,000 skills. However, these platforms are vulnerable to supply-chain attacks, as malicious contributors can embed harmful capabilities within seemingly benign reusable tools. The recent ClawHavoc supply-chain campaign (January 2026), in which more than 1,184 malicious skills bypassed existing defenses in the ClawHub marketplace, demonstrates that this risk is already being exploited at scale.

We present SkillSec, a two-stage security vetting framework that combines semantic analysis with behavioral execution. The key idea is to jointly reason over two complementary views of a skill: (i) its linguistic structure, assessed by an LLM-as-a-judge that analyzes natural language definitions for covert malicious intent, and (ii) its programmatic behavior, observed by executing the skill in a controlled sandbox and tracing its actual runtime actions. We construct a benchmark of confirmed malicious skills drawn from the live OpenClaw repository, showing SkillSec substantially outperforms all baselines and produces execution traces to verify detected threats and provide actionable evidence.

§ 2 — Threat Model

Attack Surface & Adversary Model

Open agentic platforms treat skills as AI-native software artifacts — bundles of executable scripts, configuration files, tool specifications, and natural-language instructions. This architecture introduces a multi-component attack surface that existing text-only scanners fundamentally cannot address.

🎭

Social Engineering via SKILL.md

Adversaries embed covert instructions in natural-language skill definitions that induce agents to execute attacker-controlled commands while appearing benign to human reviewers.

📦

Supply-Chain Injection

Malicious scripts bundled with legitimate skill packages exfiltrate credentials, install unauthorized dependencies, or contact external C2 servers during routine skill execution.

💉

Prompt Injection at Runtime

Adversarial inputs drive apparently benign skills into harmful behavior — stealing credentials, executing arbitrary commands, or contacting attacker-controlled endpoints — invisible to static scanners.

🔗

Compositional Attacks

Skills that appear harmless in isolation become dangerous when combined: read-then-exfiltrate or execute-then-persist chains exploit multi-step agent workflows across skill boundaries.

🔓

Privilege Escalation

Maintenance skills operating with elevated trust silently introduce remote-code-execution vectors. Repeated sudo failures are treated as obstacles, not terminal conditions, by the agent.

👁

Text-Only Scanner Evasion

Attacks that distribute malicious logic across prompt, code, configuration, and tool-call layers evade scanners that inspect only natural-language text, missing the complete attack logic.

Key insight: A skill's behavior emerges from the interaction among its prompt, code, configuration, and tool calls at runtime — not from any single component. Purely static scanners cannot model this.

§ 3 — Contributions

Key Contributions

  • C1

    SkillSec Framework. A novel two-stage vetting pipeline that combines LLM-as-a-judge semantic analysis with sandboxed behavioral execution — the first framework to jointly reason over a skill's linguistic structure and runtime behavior.

  • C2

    Four-Dimensional Risk Scoring. A structured evaluation protocol scoring each skill on (D1) prompt injection susceptibility, (D2) data sensitivity exposure, (D3) blast radius, and (D4) compositional risk — capturing threat vectors that monolithic classification misses.

  • C3

    Live Benchmark from OpenClaw. A benchmark of 100 confirmed malicious, suspicious, and benign skills drawn from the live ClawHub repository, enabling reproducible evaluation against real-world supply-chain attack artifacts.

  • C4

    Zero False Negatives. SkillSec achieves 100% detection of all 78 vulnerable skills (zero false negatives), versus 52% command injection miss rate and 84% prompt injection miss rate by the deployed OpenClaw scanner.

  • C5

    Auditable Execution Evidence. Unlike baselines that produce only binary verdicts, SkillSec generates concrete, reproducible execution traces that distinguish suspected from verified threats — enabling forensic attribution and policy enforcement.

§ 4 — Methodology

SkillSec: Two-Stage Vetting Pipeline

SkillSec analyzes a skill's natural-language instructions, executable code, configuration files, and tool-use interfaces to identify cross-component attack patterns, then executes the skill in an instrumented sandbox to capture runtime behavior.

Stage 1 — Semantic Analysis (LLM-as-a-Judge)

Rather than reducing skill evaluation to a single-label classification, SkillSec employs an LLM-as-a-judge paradigm that scores each SKILL.md file along four security dimensions. For each dimension, the LLM produces both a numerical score and a free-text justification, yielding a structured evaluation report.

D1 · Prompt Injection Susceptibility

Measures how readily a skill can be coerced into operating outside its intended purpose under adversarial prompts — whether its instruction design enforces guardrails or permits runtime hijacking.

D2 · Data Sensitivity Exposure

Quantifies the sensitivity of data a skill can access or modify — inferred from declared API endpoints, parameters, data flows, and potential handling of credentials, financial records, or PII.

D3 · Blast Radius

Captures the scope of impact from a successful exploit, distinguishing isolated single-user effects from broader consequences propagating to shared systems, multi-tenant services, or public APIs.

D4 · Compositional Risk

Assesses how much more dangerous a skill becomes when combined with others — identifying enabling roles in multi-step harmful chains (read-then-exfiltrate, execute-then-persist) that appear benign in isolation.

Stage 2 — Programmatic Analysis (Sandbox Execution)

Flagged skills are executed inside an isolated virtual machine with no access to sensitive host resources. The full OpenCLAW stack (gateway, agent, API keys) is configured to mirror realistic end-user deployment. Task prompts naturally trigger execution of flagged skills; all tool invocations, network calls, filesystem operations, and command executions are logged verbatim and audited against threat intelligence from koi.ai.

Instrumented Monitoring Surfaces

Network calls & outbound connections · Filesystem read/write/delete operations · Subprocess & exec invocations · Credential access patterns · Cross-session privilege escalation attempts · Scope drift from declared skill purpose

§ 5 — Experiments

Experimental Setup

We collected 100 skills from ClawHub.ai spanning three categories: malicious, suspicious, and benign (as labeled by ClawHub's built-in review system), comprising 78 vulnerable skills and 22 benign controls. Each skill's SKILL.md file serves as the primary input to the semantic analysis stage.

Case Study: Privilege Escalation via Autonomous Update Skill

⚠ update v1.0.0 · @timclawbot · clawhub.ai/timclawbot/update

Presents itself as a benign daily cron utility checking for, applying, and summarizing updates. Its description contains no mention of network fetches to third-party hosts, privilege escalation, or dependency installation.

Static signals: VirusTotal flagged as Suspicious. OpenClaw's code-insight engine found SKILL.md instructing macOS users to run installation from an unverified Glot.io pastebin and Windows users to download a binary from an arbitrary GitHub account. Antiy-AVL: Trojan/OpenClaw.PolySkill · Kaspersky: HEUR:Trojan.ANSI.MalClaw.gen

[Session 1] web_fetch ×2 within 4 seconds — pulling remote payloads before local execution
[Session 2] read SKILL.md → immediate exec + process sequence (~2 minutes)
[SCOPE DRIFT] Agent attempting install of polymarket v0.1.5 via uv pipeline
[BLOCKED] tools exec failed: Installing polymarket v0.1.5 (x86_64-unknown-linux-gnu)...
             Checksum verified. sudo: a terminal is required to read the password [...]
             Command exited with code 1
[Session 4] exec call at 00:34 · web_fetch at 00:42 — retrying after primary paths failed
[TOTAL] 5 sessions · ~30 minutes · 22+ tool invocations (web_fetch, read, exec, process)
⚡

Finding 1 — Static signals not propagated. Both VirusTotal and OpenClaw's scanner flagged the skill before a single tool was invoked, yet the agent proceeded without presenting these findings to the user or requesting explicit confirmation. A contextual Linux reference in the user query was treated as full authorization.

🔁

Finding 2 — Privilege escalation does not self-terminate. A sudo failure is treated as an obstacle to route around — not a terminal condition. The agent retried escalation across multiple tool calls and session boundaries, continuing for seven minutes after primary paths failed.

🎯

Finding 3 — Scope drift is a first-class attack surface. The skill's declared purpose was version checking and update application. Actual behavior encompassed fetching payloads from unverified external hosts, attempting system-wide Python package installation, and invoking polymarket v0.1.5 — blocked only by incidental environmental constraints (no TTY, Debian isolation, sudo password). In a CI environment with passwordless sudo, all three paths would have completed.
